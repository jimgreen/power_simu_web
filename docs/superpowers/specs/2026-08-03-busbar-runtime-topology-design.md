# 母线退运与混合潮流拓扑一致性设计

## 背景

模拟台允许对 `ACRealBs`、`DCRealBs` 母线图元执行投退操作。当前运行状态文件已经记录母线图元退运，但潮流计算仍沿用关联 `ACNode`、`DCNode` 的原始运行状态，导致母线退运后相邻设备继续产生功率、电流和流动箭头。

秦岭站现场状态已确认：

```text
DCRealBs.直流母线（竖向）-1.run_stat = 0
DCNode[13].run_stat = 1
DCNode[13].dead_island = false
DCNode[13].V ≈ 750 V
```

受控试验进一步发现，仅把 `DCNode[13]` 强制退运会使混合潮流在第一轮迭代失败，报 `V_DC(node 11)` 缺少独立控制方程。AC 母线退运也会出现同类问题。因此本次修复必须同时覆盖运行状态映射、混合拓扑活岛判定和无活节点子网求解，不能只在前端把量测或箭头隐藏。

## 已确认的根因

### 母线图元状态未作用于电气节点

`simu_loop.apply_dev_stat_book()` 当前只按 `dev_type + dev_name` 修改同类型模型行。`DCRealBs` 的运行状态只写入 `DCRealBs`，不会根据其 `node` 字段约束对应的 `DCNode`；`ACRealBs` 与 `ACNode` 也相同。

潮流内核以 `ACNode`、`DCNode` 为拓扑节点，因此只修改 `ACRealBs`、`DCRealBs` 不会改变任何电气连接。

### 混合拓扑错误地跨变流器共享本地参考

`hybrid_operational_island_masks()` 当前把所有运行中的 ACAC、DCDC、DCAC 变流器都视为岛之间的无条件连接，然后在整个连接分量内汇总电压参考、平衡电源、发电机和负荷。

这种判定忽略了控制模式的本地性。例如秦岭站 `ACDC变流器-1` 为 `AC=PQ, DC=NONE`。直流母线退运后，其 DC 端节点成为孤立端子，DC 侧没有电压参考，但当前算法会借用 AC 主网中的参考和平衡电源，把该 DC 岛错误保留为活岛。潮流求解器随后正确检测到该节点电压没有独立方程，并拒绝求解。

AC 母线退运时同样会留下没有本地 AC 电压、相角参考的变流器端子。受控试验中，只排除该失去本地参考的变流器，秦岭站潮流即恢复为 `iter=4, normF=2.223e-11`。

### 混合求解器不能跳过全死子网

`HybridPowerFlowCalc` 目前根据模型是否声明 AC/DC 节点创建子求解器，而不是根据拓扑中是否存在活节点创建。母线退运可能使整个 AC 或 DC 子网没有活岛，此时对应子求解器仍被创建，并报“电网中没有活节点”。

一个子网全部退运不应导致另一个仍然有效的子网停止计算。AC、DC 两侧都没有活岛时，也应得到合法的全零潮流结果，而不是仿真发散。

## 目标

- `ACRealBs`、`DCRealBs` 退运必须真实改变关联电气节点的有效运行状态。
- 母线退运后，拓扑、潮流、量测、死岛状态和 SVG 显示保持一致。
- 失去本地电压或相角参考的 AC/DC 岛不得参与潮流求解。
- 变流器只能连接两侧均满足本地求解条件的电气岛，不能把一侧的电压参考错误传递到另一侧。
- 一个 AC 或 DC 子网全部死亡时，另一个子网继续正常求解。
- 整个系统没有活岛时返回合法的全零结果，不中断仿真线程。
- AC 与 DC 母线采用对称规则，不依赖所谓的主母线。
- 母线恢复不得自动投入原本独立退运的节点或设备。

## 总体方案

采用三层一致性处理：

1. WEB 运行模型边界计算母线关联节点的有效状态。
2. 潮流拓扑按每个电气岛的本地参考条件筛选可求解岛和有效变流器连接。
3. 混合求解器跳过没有活节点的子网，并为跳过的子网生成完整的零值结果。

数据流如下：

```text
人工投退/运行状态
  -> runtime stat book
  -> 克隆源模型并应用显式设备状态
  -> 计算 RealBs 对 Node 的有效状态约束
  -> 构建 AC/DC/Hybrid PPC
  -> 本地参考与设备组成校核
  -> 选择有效 AC/DC 岛和变流器
  -> 求解仍然存活的子网
  -> 为死亡子网和无效设备生成零值结果
  -> 实时量测、device_states、SVG 灰显与流动箭头
```

## WEB 有效状态映射

### 映射关系

运行模型应用完所有显式状态后，执行以下映射：

```text
ACRealBs.node -> ACNode.idx
DCRealBs.node -> DCNode.idx
```

每个节点的最终有效状态为：

```text
节点有效状态 = 节点自身显式状态 AND 所有关联 RealBs 的状态
```

具体语义：

- 母线退运强制关联节点在本轮模型中退运。
- 母线恢复只解除母线施加的约束，不覆盖节点自身的退运状态。
- 一个节点被多个 RealBs 引用时，只有所有关联母线均运行，节点才可能运行。
- 不自动修改相邻开关、断路器、线路、变流器或电源的 `run_stat/status`。
- 相邻设备是否成为死岛由潮流拓扑自然判定。
- 每个仿真周期都从源模型克隆新的运行模型，再应用当前运行状态，因此母线恢复不会继承上一周期的派生节点退运状态。

映射在 `apply_dev_stat_book()` 完成显式设备状态、开关状态和设定值处理之后执行，在天气、负荷和能力限制处理之前完成。

若 RealBs 引用不存在的节点，不修改任何其他节点，不中断仿真；记录包含母线类型、名称和节点编号的告警，便于修复模型定义。

## 混合拓扑本地参考规则

### 本地参考不可跨域借用

每个原始 AC/DC 电气岛先独立判断本地参考：

- AC 岛必须具有本地 AC 电压、相角参考。
- DC 岛必须具有本地 DC 电压参考。
- 本地发电机、自动选择的平衡机组以及变流器对应侧的电压控制均按现有控制语义提供参考。
- `PQ/NONE` 等不提供本侧电压参考的控制模式，不能因为另一侧电网有平衡电源而获得参考。

### 有效变流器连接

ACAC、DCDC、DCAC 连接只有在以下条件全部满足时才参与混合拓扑分量计算：

- 变流器自身 `run_stat = 1`。
- 两端节点自身均运行。
- 两端所属电气岛均具备本地求解参考。

任一端不满足条件时：

- 该变流器不加入本轮 Newton 状态和方程。
- 变流器的运行状态定义保持不变，但拓扑状态为非存活/死岛。
- 两侧功率、电流和端电压结果按无效端处理，动态功率、电流输出为零。

### 设备组成与活岛判定

使用通过本地参考校核后的岛和有效变流器重新构建连接分量，再应用现有设备组成规则：

- 连接分量必须存在有效参考和平衡电源。
- 仅包含一个平衡电源且没有其他在线发电机或负荷的分量仍判为死岛。
- 不具备本地参考的岛及其发电机、负荷、支路和变流器不能参与其他分量的发电机/负荷计数。

这样可以避免一个本应死亡的负荷或发电机反过来让另一个源-only 分量被错误保留。

### PPC 与对象模型一致

WEB 实时潮流使用轻量 PPC 路径，但对象模型路径也采用相同判定语义，保证：

- PPC 与对象拓扑的 `is_alive` 结果一致。
- 文件求解、内存求解和测试构造网络结果一致。
- 状态估计和其他调用方不会获得与实时潮流相反的拓扑结论。

## 无活节点子网处理

`HybridPowerFlowCalc` 在创建 AC/DC 子求解器前读取拓扑 `node_alive_mask`：

- AC 有活节点：创建并求解 AC 子求解器。
- DC 有活节点：创建并求解 DC 子求解器。
- 某一侧没有活节点：不创建该侧子求解器，也不为该侧创建 Newton 变量或方程。
- 两侧都没有活节点：直接返回成功的空潮流结果，`iterations = 0`、`normF = 0`，不执行 Newton 迭代。

跳过子网时仍生成与原 PPC 表等长的结果表：

- 节点电压、相角等动态结果为零。
- 发电机、负荷、支路、开关、断路器和变流器功率、电流为零。
- 原始设备 `run_stat/status` 定义保留，便于区分“设备退运”和“设备运行但处于死岛”。
- `node_alive_mask`、设备 `is_alive` 和 `device_states.dead_island` 反映真实拓扑状态。

真实存在活岛但 Newton 数值不收敛时，仍按现有方式报告潮流失败，不能把数值故障伪装成全零结果。

## 输出与显示语义

修复后不在前端增加功率归零或隐藏箭头的专用补丁。前端继续消费后台结果：

- 母线本身 `run_stat = 0`，显示退运。
- 节点及被隔离设备根据有效状态和 `dead_island` 显示灰色。
- 死亡支路和设备的实时功率、电流为零。
- 流动箭头依据实时有功结果自然消失。
- 模拟台和学员台从同一实时数据链路获得一致结果。

母线恢复后，下一周期重新构建拓扑；满足自身运行状态和活岛条件的设备恢复潮流及显示，不需要刷新页面或重启仿真。

## 修改边界

WEB 仓库主要涉及：

- `simu_loop.py`：RealBs 到 Node 的有效状态映射。
- `tests/`：运行状态映射、秦岭站母线退运和量测归零回归测试。

潮流内核仓库主要涉及：

- `model/topology.py`：本地参考资格、有效岛/变流器连接与对象拓扑一致性。
- `model/ppc_topology.py`：向混合拓扑传递控制类型、本地参考和设备组成信息。
- `lfcore/hybrid_lf.py`：跳过无活节点子网、空系统成功结果和零值结果表。
- 内核 `tests/`：PPC、对象模型、求解器和结果回写回归测试。

不修改模型源文件，不生成新的 runtime 文件，不暂停仿真线程，不增加文件锁。

## 测试设计

所有生产修改按测试驱动方式实施，先建立失败测试。

### WEB 状态映射单元测试

1. `DCRealBs.run_stat = 0` 强制引用的 `DCNode.run_stat = 0`。
2. `ACRealBs.run_stat = 0` 强制引用的 `ACNode.run_stat = 0`。
3. 母线运行但节点自身退运时，节点保持退运。
4. 多个 RealBs 引用同一节点时采用 AND 语义。
5. 母线退运不修改相邻断路器、线路和变流器的显式状态。
6. 无效节点引用不会修改其他节点或中断应用流程。

### 内核拓扑测试

1. 健康 AC 主网连接一个 `PQ/NONE` DCAC 的孤立 DC 端时，该 DC 岛和变流器不存活。
2. 健康 DC 主网连接一个不提供本地 AC 参考的孤立 AC 端时，该 AC 岛和变流器不存活。
3. 两侧均有本地参考且设备组成有效时，DCAC 连接继续参与混合潮流。
4. 不具备本地参考的岛不参与连接分量的发电机、负荷和平衡源计数。
5. ACAC、DCDC 采用与 DCAC 相同的两端本地资格规则。
6. PPC 与对象拓扑对相同网络给出一致的存活状态。
7. 现有“单平衡源且无其他发电机或负荷为死岛”规则继续成立。

### 混合求解器测试

1. DC 侧全部死亡、AC 侧有效时，只求解 AC，整体正常收敛。
2. AC 侧全部死亡、DC 侧有效时，只求解 DC，整体正常收敛。
3. AC/DC 两侧都无活岛时返回成功的全零结果。
4. 跳过子网的节点、支路、负荷、发电机和变流器动态结果均为零。
5. 无效变流器不会残留上一轮功率、电流结果。
6. 存在有效活岛但数值发散时仍返回失败。

### 秦岭站端到端回归

1. 直流母线退运后，求解不发散。
2. `DCNode[13]` 不再参与拓扑，母线关联支路功率和电流归零。
3. 失去连接的风电、光伏、储能、制氢和 ACDC 设备按拓扑显示死岛或退运状态。
4. AC 主网仍可独立运行时，其潮流继续更新。
5. 交流母线退运执行对称校验，求解不出现零雅可比列。
6. 母线恢复后，原本独立运行的设备恢复；自身已退运的设备不被自动投入。
7. `real.e/scada.e`、快照 `device_states`、SVG 灰显和流动箭头结果一致。

### 回归测试

- 现有开关开合、设备投退和死岛测试继续通过。
- 现有混合 AC/DC、DCAC、ACAC、DCDC 潮流测试继续通过。
- 现有零阻抗支路、自动平衡机组和状态估计测试继续通过。
- 模拟台、学员台现有快照和 SVG 实时刷新测试继续通过。

## 验收标准

- 秦岭站直流母线退运后，仿真线程持续运行且潮流不发散。
- 退运母线不再维持节点电压，不再传递功率或电流。
- 所有被隔离设备的潮流结果、死岛状态和 SVG 表现一致。
- AC/DC 任一侧完全死亡不会影响另一侧正常计算。
- 母线恢复语义不覆盖节点和设备的独立退运状态。
- 无任何前端伪造零值、强制隐藏箭头或依赖“主母线”的判断。

## 非目标

- 不自动分合相邻开关或断路器。
- 不修改用户显式下发的设备运行状态。
- 不改变设备控制模式、设定值、容量或 SOC 逻辑。
- 不在 SVG 前端重新实现电气拓扑。
- 不以功率是否接近零反推设备投退状态。
- 不修改 `model.e` 中用户定义的原始设备状态。
