# 模拟台运行态模型与量测定义编辑设计

## 1. 目标

在模拟台 SVG 接线图的现有设备提示框和量测提示框中增加运行态定义编辑能力：

- 设备提示框允许修改模型静态参数，包括上下限、阻抗、额定参数、效率和容量等。
- 量测提示框同时显示量测值、真值、当前偏差和量测状态。
- 量测提示框允许修改误差标准差、权重和有效状态。
- 修改先作用于 WEB 后台内存定义，随后原子持久化到源 `model.e` 或 `meas.e`。
- 修改过程中不暂停仿真线程、不切换仿真状态、不重新加载 E 文件、不生成或刷新 runtime 定义文件。

采用方案 A：内存快照热替换 + E 文件原子持久化。

## 2. 非目标

本功能不负责：

- 修改设备名称、编号、类型或拓扑连接关系。
- 通过静态参数界面修改设备投退、开关开合或实时遥调值。
- 暂停、重启或重新初始化仿真。
- 从 E 文件自动刷新正在运行的仿真。
- 向 runtime 目录复制模型或量测定义。
- 改变学员台 SVG 提示框的权限和交互。

## 3. 现状与约束

当前 `PolarMicrogridSimulator._make_config()` 已把以下内存对象直接传入仿真内核：

- `source_model_book`
- `measurement_before`
- `measurement_rows`
- `measurement_after`
- `dev_define_book`
- 运行态状态、天气和控制快照

`simu_loop.run_once()` 在内存运行路径中克隆模型定义后再叠加运行态输入，正常仿真不会重新读取 `model.e` 或 `meas.e`。因此，定义编辑可以在不修改仿真线程控制方式的情况下，通过替换下一步计算所读取的定义快照生效。

现有 SVG 提示框已经支持保持 DOM 节点并增量刷新实时值。新编辑表单必须沿用这一机制，不能在每次实时轮询时重建提示框。

## 4. 定义快照

后台新增不可变定义快照，至少包含：

- `model_book`
- `dev_define_book`
- `measurement_before`
- `measurement_rows`
- `measurement_after`
- `revision`

服务初始化和显式模型重新加载时，根据源定义文件构造完整快照。运行态单字段修改不得调用现有的 `reload_definition_state()`，因为该方法会重置实时结果、量测增量状态和其他运行内存。

更新请求使用 copy-on-write：

1. 读取当前快照引用。
2. 只克隆受影响的定义对象。
3. 在克隆对象中查找并修改目标行。
4. 完成校验并重新生成依赖定义，例如 `dev_define_book`。
5. 构造 revision 增加后的完整新快照。
6. 一次性替换服务持有的快照引用。

旧快照及其中的 EBook 不得被原地修改。已经开始的仿真步继续持有旧快照；之后开始的仿真步读取新快照。

## 5. 并发模型

新增一个只供定义修改请求使用的进程内互斥锁，用于串行化两个同时到达的编辑请求，避免基于同一旧快照分别生成新快照而造成修改丢失。

该锁不是文件锁，且仿真线程不获取该锁。定义修改请求也不获取当前覆盖完整潮流计算过程的仿真锁。因此：

- 定义修改不会等待正在执行的潮流计算结束。
- 潮流计算不会等待 E 文件持久化完成。
- 单步计算只能看到完整旧快照或完整新快照，不会看到部分修改。
- 不同字段的并发修改会依次基于后台最新快照合并。
- 同一字段的并发修改采用后提交者覆盖前提交者。

## 6. 设备参数编辑

新增接口：

```text
POST /api/definitions/device-parameters
```

请求示例：

```json
{
  "model_id": "qinling",
  "block_name": "ACGenerator",
  "row_key": {
    "idx": "1",
    "name": "柴油发电机-1"
  },
  "changes": {
    "p_max": 100,
    "p_min": 20,
    "rated_capacity": 120
  }
}
```

目标行优先使用 `name` 定位，并用 `idx` 交叉确认；没有名称的组合参数表使用 `idx` 定位。请求只打补丁，不提交整行或整份 Model.e。

### 6.1 可编辑字段

允许修改非结构性的静态模型参数，例如：

- 功率、电压、SOC 等运行上下限。
- 额定容量、额定电压、能量容量。
- `r`、`x`、`b`、`r1`、`r2` 等阻抗参数。
- 充放电效率、最大充放电功率。
- 风机切入、额定、切出风速以及叶轮参数。
- 光伏组件效率、阵列面积和 MPPT 数量。
- 其他不改变设备身份、连接关系和运行状态的静态字段。

禁止修改：

- `idx`、`name`、`dev_name`、`dev_type`。
- `node`、`i_node`、`j_node`、`ac_node`、`dc_node`。
- 所有组合设备引用字段，例如 `idx_acgenerator`、`idx_dcgenerator`。
- `run_stat`、`status`、`isl`。
- 实时设定值字段和由遥控、遥调维护的运行状态。

后端是最终权限边界。前端隐藏或禁用字段不能替代后端校验。

### 6.2 数值校验

- 当前定义为数值的字段必须提交有限数值。
- 成对上下限修改后必须满足下限不大于上限。
- 容量、额定值、计数和效率等明确非负字段不得为负数。
- 不对未知单位字段增加可能误伤现有模型的额外范围假设。

## 7. 量测定义编辑

新增接口：

```text
POST /api/definitions/measurement
```

请求示例：

```json
{
  "model_id": "qinling",
  "name": "ACGenerator.柴油发电机-1.P_GEN",
  "changes": {
    "weight": 10000,
    "error_sigma": 0.01,
    "valid": 1
  }
}
```

目标量测以唯一的 `name` 定位，并可用 `dev_type`、`dev_name`、`meas_type` 交叉确认。

### 7.1 量测误差语义

现有 `meas.e` 的权重决定随机量测误差标准差：

```text
error_sigma = 1 / sqrt(weight)
weight = 1 / error_sigma^2
```

因此：

- 误差标准差和权重都可在界面编辑。
- 前端编辑其中一个时即时计算另一个。
- 后端重新计算并校验二者一致性。
- `weight` 和 `error_sigma` 必须大于零。
- E 文件仍持久化现有 `weight` 字段，不改变 Measurement 表结构。
- 当前偏差定义为 `scada_value - real_value`，仅显示，不作为持久化误差参数。

`valid` 只能是 `0` 或 `1`。修改后，WEB 返回的量测定义和量测通道应立即使用新权重与有效状态；随机误差变化从下一仿真步开始作用于 SCADA 值。

## 8. E 文件原子持久化

内存快照替换成功后，使用同一份已接受快照生成 E 文件文本。

写入流程：

1. 在目标源 E 文件同目录创建唯一临时文件。
2. 写入完整文件文本。
3. `flush` 并执行 `os.fsync`。
4. 使用 `os.replace` 原子替换目标文件。
5. 在异常路径清理临时文件。

设备参数写入源 `model.e`，量测定义写入源 `meas.e`。不得写入：

- runtime 目录中的同名文件。
- `.simu_loop_work`。
- `real.e`、`scada.e`。
- 任何新的运行态定义副本。

不得增加文件锁，也不得在持久化后通知仿真线程重新加载文件。

## 9. 持久化失败语义

操作顺序固定为“内存先接受，文件后持久化”。如果 E 文件写入失败：

- 已替换的内存快照保持有效，不执行回滚。
- API 返回 `memory_updated: true`、`persisted: false` 和明确警告。
- 当前 WEB 页面保留后台接受的新值。
- 页面提示“后台定义已更新，但 E 文件保存失败，请重试”。
- 不通过运行日志接口记录该错误，避免因此创建或修改 runtime 日志文件。
- 用户再次保存时，使用当前最新内存快照重新尝试完整原子持久化。

服务重启后只能从成功持久化的 E 文件恢复，因此持久化失败警告不能被静默隐藏。

## 10. 静态定义版本和多页面同步

`revision` 加入 `static_meta.definitions` 和 `static_meta.device_parameters`。量测定义修改也增加同一个 revision。

保存当前页面后，前端根据接口返回的目标记录立即局部更新当前快照。其他打开同一模型的 WEB 页面在下一次轻量快照轮询时发现 revision 变化，清除过期静态缓存，并只重新获取当前页面所需的静态字段。

该机制不依赖 E 文件时间戳，因此即使文件持久化失败，其他 WEB 页面仍能看到后台当前内存定义。

## 11. 设备提示框交互

设备提示框继续显示身份、运行状态、当前设定值和实时量测，并新增静态参数编辑区。

- 主设备参数按 Model.e 原始块展示。
- 通过索引关联展示 `ACWindGen`、`DCPVGen`、`DCStorageGen` 等组合参数块。
- 点击“编辑参数”后，可编辑字段切换为输入控件。
- 禁止字段保持只读。
- 编辑状态下提示框固定，不因短暂离开设备图元而关闭。
- 保存、取消或按 Esc 后退出编辑状态。
- 实时刷新继续更新运行状态和量测，但不重建编辑表单，也不覆盖脏输入。
- 保存成功后只修正受影响记录，不重新加载 SVG。

## 12. 量测提示框交互

量测提示框同时显示：

- 量测值。
- 真值。
- 当前偏差。
- 量测有效状态。
- 误差标准差。
- 权重。
- 原有小时曲线和日曲线。

点击“编辑定义”后，可以修改误差标准差、权重和有效状态。实时轮询仅更新当前值、真值、偏差、状态和曲线；已打开的表单节点和用户输入保持不变。

## 13. API 响应

成功响应至少包含：

```json
{
  "model_id": "qinling",
  "revision": 7,
  "memory_updated": true,
  "persisted": true,
  "record": {},
  "static_meta": {}
}
```

持久化失败仍返回可解析的业务响应，并把 `persisted` 设为 `false`，使前端既能接受后台新快照，又能展示不可忽略的文件保存警告。

接口仅在模拟台角色开放。学员台请求这些接口应返回未找到或禁止访问，不获得模型定义写权限。

## 14. 测试策略

严格按测试先行实现。

### 14.1 后台单元测试

- 设备参数修改立即替换内存快照。
- 旧 EBook 对象和旧行没有被原地修改。
- 当前仿真步使用旧快照，下一步使用新快照。
- 被阻塞的仿真内核不会阻塞定义保存请求。
- 参数修改正确原子写入源 `model.e`。
- 量测权重和有效状态正确写入源 `meas.e`。
- 误差标准差与权重双向换算正确。
- 持久化失败时内存新值保留，源文件保持旧内容。
- 修改前后 runtime 目录文件集合和内容签名不变。
- 身份、拓扑、运行状态字段修改被拒绝。
- 非有限数值、错误上下限和非法量测状态被拒绝。
- revision 在每次成功内存替换后递增。

### 14.2 API 测试

- 模拟台接口正确选择 `model_id` 对应的模型实例。
- 请求和响应结构符合约定。
- 学员台角色不能使用编辑接口。
- 持久化失败响应区分内存成功和文件失败。

### 14.3 前端测试

- 设备提示框识别主设备和关联参数块。
- 只允许编辑后台允许的静态字段。
- 量测框同时解析 SCADA 值和真值。
- 当前偏差不使用绝对值、上限或下限裁剪。
- 编辑误差标准差会同步权重，反向编辑同样成立。
- 实时刷新不会重建或覆盖活动编辑表单。
- 保存响应能局部更新当前快照并更新 revision。
- 持久化失败警告保持可见。

### 14.4 浏览器验证

- 仿真运行时打开设备框、修改参数并保存，时钟持续推进。
- 下一仿真步使用新参数，当前步骤不中断。
- 打开量测框可同时看到量测值、真值、偏差和状态。
- 修改权重或误差标准差后，下一步 SCADA 误差使用新参数。
- 两个模拟台页面能通过 revision 同步同一模型定义。
- 刷新页面后成功持久化的参数仍存在。
- runtime 目录没有因定义编辑新增或更新定义文件。

## 15. 验收标准

满足以下条件才视为完成：

- 设备和量测定义可在对应 SVG 提示框内编辑。
- WEB 后台先热替换完整内存快照，再原子写 E 文件。
- 仿真线程不暂停、不切换状态、不读取修改后的 E 文件。
- 单步计算不出现部分新旧定义混用。
- E 文件更新不会产生半写文件。
- runtime 目录不因本功能发生定义文件变化。
- 多 WEB 页面能观察同一后台最新定义。
- 所有新增测试和相关回归测试通过。
