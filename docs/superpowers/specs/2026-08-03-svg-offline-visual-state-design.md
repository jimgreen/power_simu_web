# SVG 退运与死岛设备灰显设计

## 背景

模拟台和学员台接线图已经能从 `device_states` 识别设备的投退状态与死岛状态，并为设备图元添加 `is-diagram-offline`。实际页面中，不同设备的灰显效果不一致：柴油发电机较明显，而盒型开关、ACDC 变流器仍保留明显的紫色或蓝色；设备关联支路也继续显示带电色。退运设备被选中后，透明度和青绿色阴影还会进一步削弱退运效果。

## 已确认的根因

1. 后台状态正确。已确认退出设备返回 `run_stat = 0`，死岛设备返回 `dead_island = true`。
2. 前端状态映射正确。对应 SVG 设备和标签已获得 `is-diagram-offline` 与 `data-diagram-operating-state`。
3. 现有 CSS 只依赖 `filter: grayscale(...)` 和 `opacity`。部分 SVG `<symbol>` 内部使用显式 `fill`、`stroke` 或电压等级颜色，浏览器对 `<use>` 应用滤镜时不能稳定、彻底地中和这些颜色。
4. 关联线路仅带有 `source-dev-id`、`target-dev-id`，没有参与设备离线状态更新，仍保持原有带电色和完全不透明。
5. `.is-diagram-offline.is-diagram-selected` 将透明度从 `0.42` 提高到 `0.62`，并使用活动状态的青绿色阴影，使被选中的退运设备看起来接近运行状态。

## 目标

- 退出运行和死岛设备必须在模拟台、学员台中稳定、明显地显示为中性灰色。
- 同一设备的图元、名称、编号、量测组和直接关联支路必须保持一致的离线视觉状态。
- 设备选中状态不能覆盖离线状态；选中离线设备仍需保持灰色，但应能看出已被选中。
- 设备恢复运行或死岛恢复后，所有关联元素自动恢复模型 SVG 原有颜色。
- 不修改模型 SVG 文件，不依赖设备类型或具体模型的专用离线图元。
- 不改变后台投退、死岛、潮流计算或流动箭头判定逻辑。

## 方案

采用“完整电气对象状态传播 + 强制中性色样式”的方案。

### 状态传播

`updateDiagramDeviceVisualStates` 每次刷新时完成两阶段处理：

1. 遍历 `[dev-id]` 和 `[dev]`，根据 `device_states` 计算设备是否离线，并建立 `offlineDeviceIds` 集合。
2. 遍历带有 `source-dev-id` 或 `target-dev-id` 的 SVG 支路。当任一端设备 ID 位于 `offlineDeviceIds` 时，为支路添加 `is-diagram-offline-connection`；否则移除该类。

设备离线条件保持现有语义：

```text
run_stat == 0 或 dead_island == true
```

不根据功率是否为零推断设备状态，也不把开关分闸直接等同于开关设备本身退出运行。开关状态继续由现有开关图元切换逻辑负责。

### 关联范围

设备离线状态应用到：

- 主设备 `<use dev-id="...">` 图元。
- 名称与编号等带相同 `dev-id` 的文本。
- 带相同 `dev="..."` 的动态量测组。
- 以该设备为 `source-dev-id` 或 `target-dev-id` 的直接连接 `path`、`line` 或其他支路元素。

只灰显直接关联支路，不递归灰显整座拓扑。下游设备是否为死岛仍由后台潮流拓扑结果决定，避免前端重复实现拓扑判断。

### 视觉规则

离线设备使用明确的中性灰色，而不是只依赖滤镜：

- 强制设置中性灰色 `color`，用于 SVG 内部的 `currentColor`。
- 对可继承的 `fill`、`stroke` 使用中性灰色覆盖。
- 保留 `grayscale(1)` 与完全去饱和作为显式颜色的补充处理。
- 普通离线设备使用较低透明度，使其与带电设备形成明显差异。
- 离线连接支路强制使用浅灰色描边并降低透明度。
- 离线文字使用比设备图元稍深的灰色，保证设备名称仍可辨认。

选中离线设备时：

- 不提高到接近运行设备的透明度。
- 不使用青绿色活动阴影。
- 使用中性灰色轮廓或阴影表示选中状态。
- 离线颜色优先级高于普通选中颜色。

流动箭头继续采用现有逻辑：关联设备离线时隐藏，不新增重复判断。

## 前端边界

模拟台与学员台分别在以下文件保持相同实现：

- `simu/web/simulator/app.js`
- `simu/web/simulator/styles.css`
- `simu/web/trainee/app.js`
- `simu/web/trainee/styles.css`

本次修改不重构两端前端文件，也不提取新的共享构建模块，避免扩大范围。测试将约束两端实现保持一致。

## 状态恢复

每次实时刷新都根据当前快照重新计算状态类：

- 离线设备恢复运行时，移除 `is-diagram-offline`。
- 关联支路没有离线端点时，移除 `is-diagram-offline-connection`。
- 恢复后不写入内联颜色，SVG 自动显示其原始电压等级颜色。
- 不重新构建 SVG，不影响当前缩放、漫游、选中设备和提示框。

## 错误与兼容处理

- 快照中找不到设备状态时，保持现有行为，不擅自判定离线。
- 同一个设备的 `dev-id`、`dev` 元素全部同步更新。
- 缺少 `source-dev-id` 或 `target-dev-id` 的普通装饰元素不参与关联支路灰显。
- 兼容 `<path>`、`<line>` 等不同支路元素类型，不依赖固定标签名。
- 不修改导入 SVG 的结构要求，已有模型无需重新导出或重新导入。

## 测试设计

按测试驱动方式实现。

### 前端静态与逻辑测试

1. `run_stat = 0` 的设备进入离线集合。
2. `dead_island = true` 的设备进入离线集合。
3. 运行设备不进入离线集合。
4. 支路任一端为离线设备时获得 `is-diagram-offline-connection`。
5. 两端均在线时移除关联支路离线类。
6. 同一设备的 `[dev-id]` 和 `[dev]` 元素同步灰显。
7. 模拟台和学员台都包含设备、关联支路与离线选中态样式。
8. 离线选中样式不再使用活动状态青绿色阴影或提高到 `0.62` 的透明度。

### 回归测试

- 现有设备离线判断测试继续通过。
- 开关开合图元切换测试继续通过。
- SVG 设备选中、提示框、缩放、漫游和流动箭头测试继续通过。

### 浏览器视觉验证

在运行中的秦岭站模型验证：

1. `ACDC变流器-2` 退出时，设备、名称、编号、量测和两侧直接支路均明显变灰。
2. `盒型开关-6` 退出时，盒型开关不再保留醒目的紫色，直接关联支路同步变灰。
3. `柴油发电机-3/4` 为死岛时保持明显灰显。
4. 点击选中离线设备后，设备仍保持灰色，但存在清晰的中性选中轮廓。
5. 设备恢复运行后，不刷新页面即可恢复原始颜色。
6. 模拟台和学员台表现一致，控制台无新增错误或警告。

## 非目标

- 不改变退运、死岛或活岛的后台计算规则。
- 不根据前端 SVG 连线重新计算拓扑。
- 不修改设备功率、量测值或控制状态。
- 不修改源 `diagram.svg`，不为每种设备增加离线符号。
- 不改变普通运行设备的颜色、选中样式或流动箭头大小。
