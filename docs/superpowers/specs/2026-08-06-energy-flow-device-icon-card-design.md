# 首页能流设备图标与信息卡片设计

## 背景

模拟台和学员台首页当前将风电、光伏、储能、负荷、柴油发电和 AC/DC 变流器直接绘制成带名称、功率和状态的整张信息卡片。设备卡片同时承担信息展示、电气接线和功率箭头承载三种职责，导致以下问题：

- 卡片边缘直接连接母线，设备本体缺少清晰的电气图元表达。
- 能流箭头和卡片边框相互挤压，设备接入关系不够直观。
- 设备状态、设备类型和实时功率集中在同一区域，视觉层级不清晰。
- AC/DC 变流器卡片覆盖交直流主干，难以区分变流器本体和信息展示区域。

用户已确认采用紧凑工业图元方案：使用实际设备图标作为电气接入节点，信息卡片只负责显示实时信息。

## 目标

- 风电、光伏、储能、负荷和柴油发电使用对应的实际设备图标。
- 设备图标接入母线和能流箭头，信息卡片不再承担接线功能。
- 直流侧使用“信息卡片、设备图标、能流线、直流母线”的排列方向。
- 交流侧使用“交流母线、能流线、设备图标、信息卡片”的排列方向。
- AC/DC 变流器图标位于交直流主干线上，信息卡片位于图标下方。
- 模拟台和学员台保持相同的 DOM 结构、设备图标、状态规则和响应式行为。
- 保留现有实时数据绑定、功率方向、动画速度、设备状态和前后端接口语义。
- 实时刷新只更新现有节点，不重建设备图元和信息卡片。

## 非目标

- 不修改后台功率汇总、拓扑分类、潮流计算或新能源控制算法。
- 不修改 `flowGroups` 数据结构及其交流、直流设备分组语义。
- 不引入外部图标服务、网络字体或新的前端运行依赖。
- 不重构模拟台和学员台的整体页面导航、状态栏、统计表格或底部面板。
- 不改变 SVG 接线图页面中的设备图元。

## 视觉方案

采用“实际设备图标 + 外展信息卡片”的紧凑工业表达。

### 设备图标

设备图标采用内置 SVG 图形，保持统一的线宽、圆角和视觉尺寸：

- 风电：风力发电机塔架和叶片。
- 光伏：带支架的光伏阵列。
- 储能：电池组或电池储能电源。
- 负荷：电气负荷或插接负荷图形。
- 柴油发电：柴油发电机组图形。
- AC/DC 变流器：带直流、交流和双向转换含义的变流器图形。

图标位于浅色方形设备节点中。设备节点使用小圆角，不使用大面积实色圆形背景，避免遮挡停运、死岛和量测异常状态。

### 信息卡片

信息卡片继续显示现有内容：

- 设备组名称。
- 当前有功功率。
- 发电、用电、充电、放电、停运、死岛或待量测状态。
- 储能 SOC。
- 在线设备数与设备总数。

信息卡片保持紧凑白底、小圆角和设备类型色左边框。卡片不绘制能流线，也不作为箭头的起止节点。

### 直流侧

每个直流设备组从外向母线排列：

```text
信息卡片 -> 设备图标 -> 能流线/箭头 -> 直流母线
```

图标始终靠近直流母线，卡片向画布左侧展开。

### 交流侧

每个交流设备组从母线向外排列：

```text
交流母线 -> 能流线/箭头 -> 设备图标 -> 信息卡片
```

图标始终靠近交流母线，卡片向画布右侧展开。

### AC/DC 变流器

AC/DC 变流器使用垂直结构：

```text
交直流主干线
      |
  变流器图标
      |
  变流器信息卡片
```

变流器图标覆盖在交直流主干线上，代表真实电气接入点。信息卡片位于图标下方，不遮挡主干线和方向箭头。

## DOM 结构

保留现有 `data-overview-group` 根节点，避免改变实时渲染入口。每个侧边设备组改为以下结构：

```html
<article
  class="energy-device energy-side-node wind"
  data-overview-group="dcWind"
  data-flow-side="left"
  data-flow-active="false"
  data-flow-direction="idle"
>
  <div class="energy-device-card">
    <span>直流并网风电</span>
    <strong data-overview-power>--</strong>
    <small data-overview-meta>等待量测</small>
  </div>
  <div class="energy-device-icon" aria-label="风力发电机">
    <!-- 内置 SVG 图标 -->
  </div>
</article>
```

交流侧使用相同元素，但通过 `data-flow-side="right"` 调整图标与卡片顺序。DOM 中不复制实时数据节点。

AC/DC 变流器根节点继续使用 `data-overview-group="acdcConverter"`，内部调整为：

```html
<article class="energy-device converter energy-acdc-converter" data-overview-group="acdcConverter">
  <div class="energy-device-icon energy-converter-icon" aria-label="AC/DC变流器">
    <!-- 内置 SVG 图标 -->
  </div>
  <div class="energy-device-card energy-converter-card">
    <span>AC/DC变流器</span>
    <strong data-overview-power>--</strong>
    <small data-overview-meta>等待量测</small>
  </div>
</article>
```

## 实时数据与状态流

现有 JavaScript 继续以 `[data-overview-group="..."]` 获取根节点，并完成以下更新：

1. 将功率写入根节点内的 `[data-overview-power]`。
2. 将设备状态、SOC 和数量写入 `[data-overview-meta]`。
3. 将能流方向写入根节点的 `data-flow-direction`。
4. 将运行状态写入根节点的 `data-operating-state`。
5. 将功率对应的颜色、线宽、箭头尺寸、透明度和动画周期写入根节点 CSS 变量。

图标、卡片和连接线继承根节点 CSS 变量。实时刷新不使用 `innerHTML` 替换设备节点，不影响动画连续性和布局稳定性。

## 能流与颜色规则

- 风电、光伏、跟网储能和构网储能图标及能流箭头统一使用绿色。
- 负荷图标和箭头继续采用现有动态负荷颜色。
- 柴油发电机图标和箭头使用红色。
- AC/DC 变流器使用青绿色。
- 交流母线和直流母线使用蓝色并保持相同显示高度。
- 功率不为零时，箭头方向和动画速度采用现有实时功率逻辑。
- 功率为零或方向为 `idle` 时，保留低透明度静态连接线，不显示方向箭头头部。
- 箭头只连接设备图标和母线，不连接信息卡片。

## 运行状态

### 正常运行

图标使用浅色底、设备色边框和设备色线性图形。信息卡片保持白底和设备色左边框。

### 退运或死岛

根节点进入 `retired` 或 `deadIsland` 状态后：

- 图标、卡片、连接线、箭头和文字整体变为中性灰色。
- 停止流动动画。
- 降低透明度，但仍保留设备名称和状态可读性。
- 不允许设备类型颜色覆盖离线灰色。

### 无有效量测

无量测状态使用虚线图标边框和虚线卡片边框，连接线降低透明度，不伪造功率方向。

### 充电与放电

储能图标不因充电或放电切换形状。方向由箭头表达，状态文本继续显示“充电”或“放电”，避免同时使用过多视觉编码。

## 响应式设计

### 常规桌面

- 图标使用稳定尺寸并紧邻母线。
- 卡片向画布外侧展开。
- 左右母线保持等高。
- AC/DC 变流器保持图标在上、卡片在下。

### 低高度桌面

- 保留完整图标、卡片、母线和箭头。
- 压缩卡片内边距、字体行高和设备列表间距。
- 不缩小图标到难以识别的尺寸。
- 交流、直流母线继续保持等高，并覆盖可见设备接入点。

### 窄屏与移动端

- 延续现有规则，隐藏母线、主干线和流动箭头。
- 设备组改为两列或单列列表。
- 每个设备项仍保持图标和信息卡片的左右结构。
- AC/DC 变流器继续保持图标在上、卡片在下。
- 文本不得与图标、其他卡片或后续内容重叠。

## 可访问性与兼容性

- 每个图标容器提供明确的设备类型 `aria-label`，内部 SVG 设置为 `aria-hidden="true"`。
- SVG 图形仅作为设备类型图标，不重复朗读卡片中的实时数据。
- 不依赖网络请求加载图标。
- 保留现有 `hidden`、`data-flow-*`、`data-operating-state` 和 `data-storage-flow` 属性。
- 当前后端仍返回旧 `flowGroups.load` 时，现有交流负荷兼容逻辑继续生效。
- 未知或未展示的设备分组不新增通用卡片，保持当前隐藏行为。

## 测试方案

实施采用测试驱动方式。

### HTML 结构测试

- 模拟台和学员台的风、光、储、荷、柴分组均包含设备图标和信息卡片。
- 不再出现中文单字图标。
- 每种设备使用对应的实际设备 SVG 图形。
- 直流侧和交流侧保留正确的 `data-flow-side`。
- AC/DC 变流器包含上方图标和下方卡片。
- 所有现有实时数据绑定属性仍存在且数量唯一。

### CSS 行为测试

- 左右设备图标与卡片顺序正确。
- 能流线和箭头定位在设备图标侧，不定位在信息卡片侧。
- 风、光、储使用绿色；负荷、柴发和变流器保留各自颜色规则。
- 交流和直流母线等高。
- 退运、死岛、无量测和零功率状态具有明确样式。
- 低高度桌面和移动端规则不会隐藏设备信息卡片。

### JavaScript 兼容测试

- 现有分组标准化、状态计算和功率渲染继续使用根节点。
- 实时更新不会替换设备根节点。
- 图标和卡片状态由根节点数据属性和 CSS 变量驱动。
- 旧 `load` 分组兼容逻辑继续映射到交流负荷。

### 浏览器验收

模拟台和学员台分别验证：

- 页面身份和主要内容正确。
- 没有框架错误覆盖层。
- 控制台无相关错误和警告。
- 常规桌面布局无重叠或裁切。
- 当前截图对应的低高度宽屏布局无重叠或裁切。
- 移动端图标与卡片排列正常。
- 实时数据刷新时功率、SOC、状态和箭头连续更新，DOM 节点保持不变。
- 至少验证一次正常运行、零功率和离线状态。

## 验收标准

1. 用户能够先通过实际设备图标识别设备类型，再从信息卡片读取实时数据。
2. 所有设备能流线都连接设备图标与对应母线，不再连接信息卡片。
3. 直流侧和交流侧的卡片方向符合已确认方案。
4. AC/DC 变流器图标接入主干，信息卡片位于图标下方。
5. 实时数据和状态刷新不产生卡片跳动或节点重建。
6. 模拟台和学员台实现一致。
7. 现有首页能流、功率汇总和交直流负荷回归测试继续通过。

## 风险与控制

- 内联 SVG 可能增加 HTML 体积。通过统一尺寸、简化路径和仅定义必要设备类型控制体积。
- 旧 CSS 伪元素可能继续作用于信息卡片。实施时以回归测试约束箭头必须挂接图标节点，并删除或收窄冲突选择器。
- 低高度布局可能因图标列增加而压缩卡片宽度。通过稳定图标宽度、外展卡片和浏览器几何检查控制。
- 模拟台和学员台文件存在重复实现风险。通过成对测试和浏览器对照验收确保两端一致，不在本次任务中扩大到构建系统重构。
